# Experimental native arithmetic/import diagnosis — not package acceptance

The original candidate, scientific fixture, tests and exact 48-null oracle are
unchanged. `primitive-diagnosis.yml` runs sequential Intel then ARM on standard
public macOS runners, R 4.6.1, no caches/private fallback or paid runners.

The small C++ probe compares original Boost integer API, explicit no-promote and
64-bit binary-mantissa software evaluation (expression templates off), using the
**original input-type dispatch** and per-function double casts before subtraction.
It saves actual binary64 bits/hexfloat/decimal and numeric-limits/compile/source/
BH provenance. A separate Wide-only source-string constant construction control
must route before digamma/trigamma definitions, execute both D53/D64 construction
counters, and leave every non-Wide native result bit-identical. This is hypothesis
instrumentation, not a production fix or proof of Intel extended-precision parity.

Only ARM rebuilds exact upstream SummarizedExperiment 1.43.0 source, excludes the
single earlier S4Arrays import, verifies the unchanged DelayedArray effective
provider in fresh processes and demands no derived-load warnings. Exact original
archives, all original source hashes/MD5, derivative diffs/notices/licences and
regenerated MD5 are retained. No installed namespace edit or warning suppression.

Exactly one ARM smoke then tests a **separate experimental fgsea 1.39.2 derivative**
with betaMeanLog-only software64 digamma evaluation. Trigamma, statistical formulas,
sampleSize, RNG, tests, fixture, serialisation and IDs code remain original; every
digamma value is cast to double before subtraction. No forced-string constant
override is enabled in this derivative. Its output may still fail the unchanged
oracle. Any primitive/prototype success is DIAGNOSTIC ONLY and does not establish
full native ordinary/longtests or authorize adoption/deletion.
